# 0005 — i18n with Angular's built-in tooling

## Context

The UI is Spanish (es-MX) only for now. Hard-coded strings would make a second language a rewrite, and dates must read as Spanish local days.

## Decision

- `@angular/localize` with Spanish as the **source locale** (`sourceLocale: es-MX`). One build, no translation files until a second language exists.
- Every user-facing text in templates carries `i18n` / `i18n-<attr>` with a custom ID; in TypeScript, `` $localize`:@@id:Texto` ``. Lint fails on unmarked text.
- Dates and numbers go through Angular pipes with the es-MX locale registered at bootstrap.

## Consequences

- Adding English later is a translation file and a second build target.
- Book names come from the catalog data, not from i18n: they are data (Reina-Valera names), not UI copy.

## Rejected

- **ngx-translate / Transloco** — runtime loading and extra dependencies for a single language.
